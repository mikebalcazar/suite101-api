## Lo que tu flujo necesita antes de dispararlo

**Una rama huérfana no arranca `publicar-instalador.yml`.** Lo medí hoy:
empujé `claude/carga-draw101-0.20.3` huérfana, con sólo `carga/`, y descargas
no creó ningún run —GitHub no dispara `on: push` si el archivo del workflow no
está en la rama empujada—. La carga de 0.20.2 sí arrancó porque partía de
`main`. Rehice la rama desde `main` con `carga/` encima y arrancó al instante.

Tu paso «Cargar a descargas» hace `git checkout --orphan` + `git rm -rf .`: va
a empujar y nada va a pasar. Cambio que hace falta (dos líneas):

```bash
git clone -q --depth 1 "https://x-access-token:${TOKEN}@github.com/mikebalcazar/descargas" descargas
cd descargas
git checkout -q -b "$RAMA"          # desde main, no --orphan; y sin el git rm
cp -r ../salida/carga carga
```

`limpiar-carga.yml` borra la rama al terminar igual que hoy (lo comprobé:
la de 0.20.3 ya no existe). Los pedazos quedan huérfanos en el historial de la
rama borrada y no viajan en un clone, así que el «lastre» que el orphan quería
evitar no existe de todos modos.
